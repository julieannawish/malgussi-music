# 말구씨 음악앱 V4.31

## V4.31 — 안드로이드 공용 지원 강화 (PWA 설치/매니페스트)

핵심 코드는 이미 크로스플랫폼(기능 감지 기반, iOS 전용 하드코딩 없음)이라 안드로이드
크롬에서 그대로 실행된다. 이번에는 안드로이드 설치 경험을 다듬었다.

### 변경 내용
- **매니페스트 보강**: `id`, `description`, `lang`, `scope`, `orientation:portrait`,
  `categories`, 그리고 **maskable 아이콘**(`app-icon-maskable.png`, 안전 여백 포함)
  추가 → 안드로이드 설치 아이콘·배너 품질 향상.
- **홈 화면 설치 버튼**: 설정 화면에 추가. 안드로이드/데스크톱 크롬의
  `beforeinstallprompt`를 받아 "📲 홈 화면에 설치" 버튼을 노출하고, 설치 후 자동
  숨김. iOS Safari는 이 이벤트가 없어 버튼이 표시되지 않으며(아이폰은 공유 메뉴로
  설치) 기존 동작에 영향 없음.
- **standalone 메타 태그** 추가(`mobile-web-app-capable` 등)로 전체 화면 실행 강화.

### 플랫폼 차이(참고)
- 안드로이드 크롬은 `showDirectoryPicker`(폴더 핸들 영구 권한)를 지원 → iOS보다
  파일 복원이 더 안정적. 앱은 기능 감지로 자동으로 더 나은 경로를 사용한다.
- 안드로이드는 저장 용량이 크고 Media Session(잠금화면/알림 제어)이 강력해
  MP4 잠금화면 제어도 대체로 동작한다.

## V4.30 — 잠금화면에서 재생 시 소리가 안 나던 문제 수정

증상: 잠금화면에서 커버는 잘 나오는데(V4.29), 재생 버튼을 누르면 MP3·MP4 모두
소리가 안 남.

원인/수정:
- MP4 자동재생이 iOS에 막히면 **음소거로 재생 후 다시 음소거를 해제하지 않아**
  이후 재생이 무음이 됐다. 또 잠금화면 재생을 `fromUserGesture=false`로 처리해
  소리 출력이 억제됐다.
- 잠금화면/Media Session 재생은 iOS에서 **사용자 활성화**로 인정되므로 이제
  `fromUserGesture=true`로 처리하고, 실제 재생 시 **음소거 해제 + 볼륨 100%**로
  설정한다(`playActiveMedia`, Media Session play 핸들러).

## V4.29 — G4 잠금화면 MP4 커버가 안 나오던 문제 수정

증상: 잠금화면(iOS Media Session)에서 MP4의 커버 이미지가 안 나오고, 이전/재생/
다음 버튼도 동작하지 않음.

원인/수정:
- **커버**: Media Session 아트워크에 `blob:` URL을 넣었는데 iOS는 blob: URL을
  거부한다(그래서 커버가 아예 안 뜸). **data: URL**로 바꿔 iOS가 표시하도록 수정.
- **MP4 프레임 커버**: 재생 중인 **실제 영상 프레임을 캡처**해 잠금화면 커버로
  사용(iOS는 재생 중 디코딩된 프레임만 캡처 가능).

한계(iOS 플랫폼): 아이폰은 **영상(video)을 백그라운드/잠금 시 정지**시키고, 잠금화면
컨트롤도 오디오와 다르게 처리한다. 그래서 MP4의 잠금화면 이전/다음 버튼은 iOS
정책상 오디오처럼 동작하지 않을 수 있다. MP3(음악)는 백그라운드 재생이 유지되어
잠금화면 제어가 정상 동작한다.

## V4.28 — 저장 요약이 "모두 연결됨인데 N-1/N(빨강)"으로 깜빡이던 문제 + MP3 커버

문제 1 (저장 요약 N-1): 새 곡을 추가하면 모두 `연결됨`인데 상단 요약은 계속
빨간 `2/3` 등으로 곡 수보다 하나 적게 표시됐다.
원인: `loadCurrent`가 현재곡을 로드할 때마다 `saveTrackFile`을 다시 호출하는데,
그 저장이 기존 레코드를 "삭제→재기록"하는 사이의 짧은 순간에, 동시에 도는 저장
요약 검사가 그 곡을 "없음"으로 읽었다(레이스). 대용량은 매번 재청크까지 해서 창이
더 길었다.
수정: 이미 같은 크기의 저장본이 있으면 `saveTrackFile`이 **재기록을 건너뛴다**
(불필요한 재청크 제거, 성능 향상). 소용량 저장도 삭제+기록을 **한 트랜잭션**으로
묶어 레코드가 순간적으로 사라지지 않게 했다.

문제 2 (MP3 커버): 이전/다음으로 이동하면 커버 추출을 건너뛰어(fastBoot) 앨범
아트가 있는 MP3도 커버가 안 떴다.
수정: 이동 후 **백그라운드로 커버를 추출해 채운다**. 단, 파일에 내장 앨범 아트가
없는 MP3는 원래대로 기본 강아지 이미지가 표시된다(정상 동작).

## V4.27 — 저장공간 표시 + 고아 저장분 자동 정리

배경: 추가 직후 진단이 `1/2`(빨강)로, MP4 한 곡이 실제로 저장되지 않았다. 이는
메시지 동기화 오류가 아니라(추가 핸들러는 저장을 모두 기다린 뒤 표시함) 실제
저장 실패다. 그동안 버전을 여러 번 올리며 재추가한 옛 데이터가 저장소에 쌓여
(각 추가가 새 track id를 만들어 옛 id의 조각/블롭이 남음) 용량 한도를 채운 것이
유력한 원인.

### 수정 내용
- 재생목록에 없는(삭제됐거나 옛 버전의) track id의 저장 바이트를 **자동 정리**
  (`cleanupOrphanTrackStorage`). 부팅 시, 그리고 파일 추가 직전에 실행하여 새
  파일이 들어갈 공간을 확보한다.
- 재생목록 관리 화면 진단에 **저장공간 사용/한도(MB)**를 함께 표시하여, 저장
  실패가 용량 한도 때문인지 바로 확인할 수 있게 했다.

## V4.26 — ★버전 배포 때마다 저장 파일이 지워지던 치명 버그 수정

증상: 새 버전을 배포/실행할 때마다 이전에 잘 저장됐던 파일(특히 MP4)이 다시
`원본 없음`이 되고, 진단이 `1/2`처럼 줄었다. "아까 고친 게 다시 재발".

원인(핵심): `sw.js`의 서비스워커 activate 단계가 오래된 앱 캐시를 지울 때
`malgussi-`로 시작하는 **모든** 캐시를 지웠는데, 사용자의 저장 파일이 담긴
`malgussi-track-cache-v5`도 여기에 걸려 **버전 배포마다 통째로 삭제**됐다.

### 수정 내용
- 서비스워커가 **앱 셸 캐시(malgussi-vNNN)만** 정리하고, 파일 저장 캐시
  (`malgussi-track-cache-*`)는 **절대 삭제하지 않도록** 필터를 수정.
- 재생목록 관리 화면에서 **삭제/중복삭제 시** 저장 캐시를 실제로 지운 뒤
  상단 `앱에 저장됨 N/M곡` 요약을 갱신하도록 동기화(추가는 기존에도 동기화됨).

주의: 이 버그 때문에 그동안 버전 올릴 때마다 저장이 날아갔다. V4.26부터는
버전을 올려도 저장 파일이 유지된다.

## V4.25 — 재생 전 타임바(길이)·MP4 커버가 안 나오던 문제 개선 (iOS)

증상: V4.24로 제목은 나오는데, 재생을 누르기 전 기본화면에서 타임바가 00:00/00:00,
MP4 커버가 검게 나옴.

원인: iOS Safari는 재생(play) 전에는 미디어 메타데이터(길이)와 영상 프레임을
디코딩하지 않는다. 그래서 연결만 된 상태에서는 길이·프레임을 얻을 수 없다.

### 수정 내용
- 곡 길이를 한 번 알게 되면(재생 시) 트랙 정보에 캐시하고, 이후에는 기본화면에서
  **캐시된 길이를 즉시 타임바에 표시**한다.
- MP4는 `<video poster>`(디코딩 불필요 이미지)로 재생 전 커버를 표시한다. 내장/캐시
  커버가 있으면 그것을, 없으면 기본 강아지 이미지를 보여준다.
- 한계: 한 번도 재생하지 않은 곡은 iOS가 길이를 주지 않아 처음엔 00:00일 수 있고,
  MP4 프레임 커버도 최초 재생 이후에 캐시된다. 재생을 한 번 하면 이후로는 표시된다.

## V4.24 — 관리 화면에서 복귀 시 기본화면에 현재곡이 안 뜨던 문제 수정

증상: 재생목록에 곡이 있고(하단 `2곡 중 1곡`은 정상) 재생목록 관리에서 원본이
연결됐는데도, 기본화면으로 돌아오면 위쪽에 `음악 또는 동영상을 넣어 주세요`가
그대로 남고 첫 곡의 제목·커버·타임바가 표시되지 않았다.

원인: `close('v352Playlist')`가 (1) 곡을 바꿨거나 (2) 재생 중이었을 때만 기본화면을
갱신하고, "그냥 닫기"의 경우 아무것도 하지 않았다. 부팅 때 연결이 안 됐다가 관리
화면에서 비로소 연결된 경우, 기본화면이 빈 상태로 남았다.

### 수정 내용
- 관리 화면을 닫을 때 현재곡이 연결돼 있으면(아직 플레이어에 로드되지 않았다면)
  **자동재생 없이** 기본화면에 제목·커버·타임바를 로드한다(`loadCurrent(false)`).

## V4.23 — 대용량 MP4가 재실행 후 `원본 없음` 되던 문제 수정 (조각 저장)

증상: V4.22에서 MP3(음악)는 재실행 후 `연결됨`으로 잘 복원되는데, MP4는 계속
`원본 없음`. 진단도 `1 / 2곡`으로, MP4만 실제 저장이 안 됨을 정확히 보여줬다.

원인: iOS에서 확인된 사실 —
- 실제 바이트를 IndexedDB에 저장한 파일(소용량 MP3)은 재실행 후에도 살아남는다.
- 원본 File을 그대로 Cache Storage에 스트리밍한 파일(대용량 MP4)은 참조로만 저장돼
  앱을 닫으면 사라진다.
즉 V4.22의 "대용량은 Cache Storage 스트리밍" 전략이 iOS에서 통하지 않았다.

### 수정 내용
- 대용량 파일도 **실제 바이트를 IndexedDB에 저장**한다. 단, 큰 MP4를 한 번에 메모리에
  올리면 iPhone이 죽으므로 **약 6MB 조각(chunk)으로 나눠 저장**하고, 재생 시 다시 이어
  붙인다(조각은 디스크 기반이라 재생은 스트리밍된다). 메모리 안전 + 재실행 영구.
- 소용량은 종전대로 통째로 materialize하여 IndexedDB + Cache Storage 이중 저장.
- 삭제/복원/진단이 조각 구조를 함께 처리하도록 정리.

한계: 단일 MP4가 iPhone의 오프라인 저장 한도 자체를 넘으면 저장이 실패할 수 있다.
이 경우 재생목록 관리 화면의 `앱에 저장됨: N / M곡` 진단에서 즉시 확인된다.

## V4.22 — 저장은 됐는데 재생목록에 `원본 없음` 표시되던 문제 수정

증상: V4.21에서 파일이 앱에 영구 저장되어(진단 `앱에 저장됨 2/2곡`, 재실행 후에도 2/2)
있는데도, 재생목록 관리 화면에는 여전히 `원본 없음`으로 표시됨.

원인: 재생목록 관리 진입 시 실행되는 `ensurePlaylistSources()`가 파일을 fileMap에
연결할 때 **파일명 미디어 캐시와 폴더 핸들만** 조회하고, 실제로 파일이 저장된
**per-track 캐시(trackId 기준 IndexedDB/Cache Storage)는 조회하지 않았다.**
아이폰에는 폴더 핸들이 없어 이 경로가 유일한 원본 위치인데 누락되어 있었다.

### 수정 내용
- `ensurePlaylistSources()`가 가장 먼저 `restoreTrackFileMap()`으로 per-track 캐시에서
  fileMap을 복원하도록 변경. 저장돼 있으면 즉시 `연결됨`으로 표시된다.
- 진단(`앱에 저장됨 N/M곡`)이 헤더가 아니라 **실제 저장된 본문 크기**를 확인하도록
  정확화하여, 복원 가능 여부와 정확히 일치하게 했다.

## V4.21 — 버전 표기 상향(배포 확인용) + 저장 견고성 유지

- 배포된 버전이 이전과 다른지 화면에서 바로 확인할 수 있도록 버전만 V4.20 → V4.21로 올렸다.
- V4.20의 저장 구조(대용량은 Cache Storage 스트리밍 저장, 소용량은 IndexedDB 이중화)와
  재생목록 관리 화면의 `앱에 저장됨(재실행 복원 가능): N / M곡` 진단 표시를 그대로 유지한다.
- 기능 로직 변경은 없다.

## V4.20 — iPhone 재실행 후 재생목록 `원본 없음` 근본 수정

증상: 설정에서 아이폰 최상위 폴더를 지정하고 재생목록 관리에서 MP3·MP4를 각각
추가한 뒤 앱을 완전히 종료했다가 다시 열면, 재생목록의 곡 수(2곡)는 복원되지만
파일이 모두 `원본 없음`으로 표시되고 자동 재생도 되지 않는다.

원인: iOS/WebKit은 `<input>`으로 고른 File을 IndexedDB/Cache Storage에 저장할 때
실제 바이트가 아니라 임시 파일에 대한 **참조**로 저장할 수 있다. 세션 중에는
읽기·검증이 통과하지만(그래서 추가 시 에러가 없음) PWA를 종료하면 임시 파일이
사라져, 재실행 시 저장 블롭이 빈 값으로 읽힌다. 크기와 무관하므로 MP3·MP4가
모두 `원본 없음`이 된다.

### 수정 내용
- 저장 직전 File을 `arrayBuffer()`로 읽어 실제 바이트 Blob으로 복제(materialize)한 뒤
  IndexedDB와 Cache Storage에 저장한다. 재실행 후에도 바이트가 그대로 남는다.
  (`saveTrackFile`, `saveTrackFileToCacheAPI`, `cacheMediaFiles`)
- 대용량 파일은 동일 바이트를 한 곳에만 저장해 아이폰 저장 용량 압박을 줄인다(25MB 기준).
- 재생목록 관리 화면 진입 시 저장된 폴더 핸들의 읽기 권한을 재요청하도록 보완
  (데스크톱 브라우저 재시작 후 권한 리셋 대응, iOS에는 영향 없음).

## V4.19 — 기본 폴더 하위 폴더 MP4 재연결/캐시 구조 수정

이번 버전의 핵심은 **기본 폴더를 휴대폰 최상위 폴더로 지정하고 그 아래 하위·하위하위 폴더의 MP4를 재생목록에 넣은 뒤 앱을 다시 실행했을 때 `원본 없음`으로 바뀌는 문제**입니다.

### 수정 내용
- 기본 폴더 전체를 한 번에 IndexedDB에 복사하던 방식을 제거하고, **재생목록에 실제 포함된 파일만 trackId 기준으로 캐시**합니다.
- 한 개의 큰 MP4가 저장 용량/트랜잭션 문제를 일으켜도 다른 파일의 캐시가 함께 실패하지 않도록 **파일별 독립 저장**으로 변경했습니다.
- IndexedDB 저장에 실패하는 경우 Cache Storage를 **2차 캐시**로 사용합니다.
- 앱 재실행 시 `trackId → IndexedDB → Cache Storage → 기본 폴더 Handle 재귀 탐색 → 파일명/크기/경로 매칭` 순서로 복구합니다.
- 하위 폴더/하위하위 폴더는 계속 재귀 탐색합니다.
- 자동 재연결에서 `원본 없음` 항목을 삭제하지 않습니다.
- 폴더 전체를 스캔해도 재생목록에 없는 파일을 캐시하기 위해 대용량 저장공간을 불필요하게 사용하지 않습니다.
- MP4를 다시 선택하면 기존 trackId에 원본을 재연결합니다.
- V4.13까지의 3종 버튼, 프로그레스바, 현재곡 하이라이트, 연속/랜덤/한곡반복, 재생목록 이동 중 재생 유지 로직을 유지합니다.

## 이번 버전 핵심 수정
- 재생 중 `재생목록 관리`로 이동해도 현재 MP3/MP4 재생을 **중지하지 않음**
- 재생목록 화면에서 현재 재생곡 자동 스크롤/하이라이트 유지
- 재생 중 재생목록을 열었다 닫아도 동일 곡의 재생 상태를 유지

- Media Session 상태 및 잠금화면 이전/재생/다음 핸들러 유지
- MP4 전체화면 진입 버튼 추가
- MP3도 동일한 전체화면 버튼으로 커버/재생 영역을 크게 볼 수 있도록 추가
- iPhone에서는 MP4의 경우 지원되는 환경에서 native video fullscreen을 우선 시도
- 연속재생/랜덤재생/한 곡 반복 3버튼 균등 배치 및 연속재생 기본값 유지
- MP4 프레임 내부 기본 컨트롤/시간바 제거 유지
- MP3→MP4 실제 재생 상태와 외부 3종 세트 상태 동기화 유지
- 기본 미디어 하위 폴더 재귀 탐색 및 재생목록 원본 동기화 유지
- 정상 상태에서 stale `음악 폴더를 선택해 주세요.` 메시지가 남지 않도록 유지
